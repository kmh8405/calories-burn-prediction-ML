# 🧪 Calorie Burn Prediction (Original Experiment)

이 디렉토리는 대회 당시 진행했던 **원본 실험 코드와 과정**을 담고 있습니다.
최종 제출 기준으로 가장 높은 성능을 기록했던 버전입니다.

---

## 📌 프로젝트 개요

운동 데이터(심박수, 운동 시간, 체온, 신체 정보 등)를 기반으로 **칼로리 소모량을 예측하는 회귀 모델**을 구축하는 것이 목표였습니다.

---

## 📁 Data

본 프로젝트는 대회 데이터를 기반으로 진행되었으며, 데이터는 저작권 및 정책상 레포지토리에 포함되어 있지 않습니다.

실행을 위해 아래와 같은 구조로 데이터를 직접 추가해야 합니다:

```bash
data/
├── train.csv
├── test.csv
├── sample_submission.csv
```

> `data/` 디렉토리는 `.gitignore`에 포함되어 있어 GitHub에는 업로드되지 않습니다.

## 🧠 접근 방식

초기에는 단순한 모델부터 시작하여 점진적으로 복잡도를 높이는 방식으로 진행했습니다.

### ✔ 초기 시도

* XGBoost 단일 모델

### ✔ 중간 단계 실험

* CatBoost 단일 모델 + Optuna
* Boosting 모델 3종 앙상블 (XGB + LGBM + CAT)
* Stacking (ElasticNet / Ridge)

### ✔ 후반 실험 (다양한 구조 탐색)

* Base model 5개 + Ridge Stacking
* Base model 4개 + Ridge Stacking
* Stacking 구조 4가지 이상 변형 실험
* 다양한 Feature 조합 실험

> 성능 개선을 위해 구조, 변수, 학습 방식 등 거의 모든 요소를 반복적으로 실험했습니다.

---

## ⚙️ 핵심 아이디어

### 1️⃣ Target 재정의 (핵심)

* **총 칼로리 → 분당 칼로리(rate)로 변환 후 학습**
* 이후 `운동 시간 * 예측 rate`로 복원

👉 효과:

* 타겟 분포 안정화
* 모델 학습 효율 개선

---

### 2️⃣ Feature Engineering 중심 접근

단순 변수 사용이 아닌,
→ **생리학 기반 + 상호작용 기반 파생 변수 생성**

예시:

* BMI, BMR
* HR Ratio (심박 비율)
* 운동 강도 지표 (Intensity, Effort)
* 고강도 구간 변수 (High Burn Zone)
* 비선형 변환 (log, sqrt 등)

> 실제 성능 향상의 대부분은 Feature Engineering에서 발생했습니다.

---

### 3️⃣ Clustering Feature 추가

* Gaussian Mixture Model 사용
* Cluster → One-Hot Encoding

→ 데이터의 숨겨진 구조를 반영하기 위한 시도

---

### 4️⃣ 모델 전략

* XGBoost / LightGBM / CatBoost 비교
* 모델별 Feature Selection 별도 수행
* Optuna 기반 하이퍼파라미터 튜닝

---

### 5️⃣ 앙상블 (Stacking)

* Base Model: CAT / XGB / LGBM
* Meta Model: Ridge

→ 단일 모델 대비 성능 향상 확인

---

### 6️⃣ SHAP 기반 후처리

* 고강도 구간에서 **Under-predict 현상 발견**
* 특정 구간에 대해 **후처리 보정 적용**

---

## 🔧 Data Preprocessing

모델 성능 향상을 위해 다음과 같은 전처리를 수행했습니다:

* 단위 변환 (키, 몸무게, 체온)
* 범주형 변수 인코딩 (Gender, Weight_Status)
* 생리학 기반 파생 변수 생성

  * BMI, BMR
  * 최대 심박수(Max HR), HR Ratio
* 운동 강도 및 효율 관련 변수 생성

  * Intensity, Effort, High Burn Zone
* 비선형 변환 적용

  * log, sqrt 등
* 이상치 대응을 위한 파생 변수 생성

> 단순 정제 수준을 넘어, 모델이 학습하기 쉬운 형태로 데이터를 재구성하는 데 초점을 두었습니다.

## ⚠️ 한계 및 회고

대회 종료 후 다른 팀 발표를 통해 다음과 같은 점을 확인했습니다.

### 1️⃣ 핵심 도메인 공식 활용 부족

* **Keytel 공식 기반 변수**가 매우 강력한 feature였음
* 해당 변수 활용 시 단순 모델로도 매우 높은 성능 가능

→ 일부 팀은
Keytel 기반 변수 + 간단한 모델만으로 **0.0x 성능 달성**

---

### 2️⃣ Target 특성 활용 부족

* 실제 정답 값이 float 형태지만 **정수 형태 (xx.0)**

→ 단순 **반올림 처리만으로도 성능 개선 가능**
→ 약 0.1 수준의 RMSE 감소 효과 추정

---

### 3️⃣ 모델 복잡도

* 일부 팀은 변수 4~5개만으로도 높은 성능 달성
* 본 프로젝트는 상대적으로 복잡한 구조 사용

---

### 4️⃣ Reverse Engineering 접근 부족

상위 팀 접근 방식:

1. CatBoost + Feature Engineering + Optuna
2. Keytel 공식 기반 Linear Regression
3. Target 정수화
4. 단위 변환 후 정수화
5. 데이터 역공학

→ 본 프로젝트에서는 해당 접근을 사용하지 않음

---

## 💡 배운 점

* Feature Engineering이 모델보다 중요할 수 있음
* 단순한 접근이 더 강력할 수 있음
* 데이터의 구조를 이해하는 것이 핵심
* 성능 개선에는 “정답에 가까운 방향성”이 존재함
* 복잡한 모델보다 **문제 정의가 더 중요함**
